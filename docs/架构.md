## 二、核心数据模型

```sql
-- 工作流定义
CREATE TABLE workflows (
    id UUID PRIMARY KEY,
    name TEXT NOT NULL,
    description TEXT,
    yaml_definition TEXT NOT NULL,  -- 原始 YAML
    version INT DEFAULT 1,
    created_at TIMESTAMP DEFAULT NOW()
);

-- 任务执行实例
CREATE TABLE tasks (
    id UUID PRIMARY KEY,
    workflow_id UUID REFERENCES workflows(id),
    status TEXT NOT NULL, -- pending/running/paused/completed/failed/rolled_back
    trigger_type TEXT,    -- manual/github_issue/cron
    trigger_payload JSONB,
    git_repo TEXT,
    git_branch TEXT,
    sandbox_id TEXT,
    created_at TIMESTAMP DEFAULT NOW()
);

-- 步骤执行记录
CREATE TABLE step_executions (
    id UUID PRIMARY KEY,
    task_id UUID REFERENCES tasks(id),
    step_name TEXT NOT NULL,
    step_type TEXT NOT NULL, -- analyze/approval/execute/review/merge
    status TEXT NOT NULL,    -- pending/running/waiting_approval/completed/failed
    input JSONB,
    output JSONB,
    ai_model TEXT,
    token_usage JSONB,
    started_at TIMESTAMP,
    completed_at TIMESTAMP,
    error_message TEXT
);

-- 审批记录
CREATE TABLE approvals (
    id UUID PRIMARY KEY,
    step_execution_id UUID REFERENCES step_executions(id),
    status TEXT NOT NULL,  -- pending/approved/rejected
    approver TEXT,
    comment TEXT,
    decided_at TIMESTAMP
);
```

### 为什么选 Temporal

| 特性 | 优势 |
|------|------|
| 工作流即代码 | TypeScript/Python/Go SDK 定义工作流 |
| 自动重试 | 步骤失败自动重试，可自定义策略 |
| 持久化执行 | 服务重启不会丢失正在执行的工作流 |
| 超时控制 | 支持 workflow timeout / activity timeout / heartbeat timeout |
| 审计日志 | 每次 Activity 的输入/输出/耗时全部记录 |
| 信号机制 | 用于审批等需要外部输入的场景（WaitForApproval = 等待 Signal） |

## 四、AI Agent 调用层

### 设计原则

> **不对 Agent 框架产生依赖。** 直接调 Claude/OpenAI API，用固定 Prompt 模板 + 结构化输出。

```typescript
// 示例：Analyze Activity
async function analyzeIssue(issue: Issue, codebase: string) {
    const prompt = ANALYZE_TEMPLATE
        .replace('{{ISSUE}}', issue.body)
        .replace('{{FILES}}', codebase);

    const response = await anthropic.messages.create({
        model: 'claude-sonnet-4-20250514',
        max_tokens: 4000,
        system: SYSTEM_PROMPT_ANALYZE,
        messages: [{ role: 'user', content: prompt }]
    });

    return parseAnalysisPlan(response.content[0].text);
}
```

### Prompt 模板策略

| 步骤 | Prompt 核心 |
|------|------------|
| analyze | "你是资深工程师。阅读这个 Issue 和相关代码，输出修复方案（JSON）。不要写代码。" |
| execute | "你只能修改方案中列出的文件。保持改动最小化。每一步说明原因。" |
| review | "审查以下 diff。标注：严重 bug、安全问题、代码风格、是否达到目标。" |

## 五、安全设计

| 层 | 措施 |
|----|------|
| 沙箱隔离 | 每个任务独立 Docker 容器，任务结束销毁 |
| 网络限制 | 沙箱只能访问 GitHub API + AI API |
| 文件系统限制 | 只挂载目标 repo，不能访问宿主机 |
| Token 限额 | 每任务最大 token 硬上限，超限自动终止 |
| 操作白名单 | 禁止 Agent 执行 `rm -rf`、`DROP TABLE`、`git push --force` 等危险命令 |
| 审批节点 | 写操作（commit/push/PR/merge）必须在审批步骤之后 |
