# 商业计划

## 一、商业模式

### 阶段 1: 开源核心 + 社区 (0 → 1)

```
产品形态：开源 CLI + Web Dashboard
收入：$0
目标：1000 GitHub Stars + 活跃社区
时间：6 个月
```

**开源策略**：
- 核心编排引擎完全开源
- 单机可运行，开发者自己部署
- 社区贡献工作流模板

### 阶段 2: SaaS 免费 + 付费 (1 → 100)

| Plan | 价格 | 内容 |
|------|------|------|
| **Free** | $0 | 个人使用，每月 50 次 Agent 执行，公开仓库 |
| **Team** | $29/seat/月 | 无限执行，私有仓库，审批流，团队仪表盘 |
| **Enterprise** | 议价 | SSO、私有部署、合规审计报告、SLA |

### 阶段 3: 企业私有化 (100 → 1000)

| 模式 | 价格 | 适用 |
|------|------|------|
| 私有部署 License | $50K-200K/年 | 银行、保险、政府 |
| 专属托管 (VPC) | $10K-50K/月 | 中型企业 |
| 定制开发 | 议价 | 特定行业需求 |

## 二、市场进入策略

### 2.1 内容驱动获客

| 渠道 | 内容方向 |
|------|----------|
| **Twitter/X** | "Agent 翻车合集"系列 —— 天然传播素材 |
| **Hacker News** | 发布开源时投：Show HN: Agent Orchestrator |
| **博客/Dev.to** | "为什么你的团队不该让 Agent 直接碰生产代码" |
| **YouTube** | Agent 编排 vs 直接 Agent 的对比演示 |
| **Reddit** | r/programming, r/MachineLearning, r/devops |

### 2.2 社区冷启动

1. **开源 CLI 工具** — `agent-logger`：给 Claude Code / Cursor 的执行加上日志
2. **打入开源项目** — 给知名项目当 CI Agent（自动 triage issue / review PR）
3. **工作流模板市场** — 激励社区贡献模板，网络效应

### 2.3 企业触达

| 阶段 | 方式 |
|------|------|
| 早期 | 创始人直接 BD，找到 3-5 个设计合作伙伴 |
| 中期 | 通过 YC / TechCrunch / 行业会议曝光 |
| 后期 | 企业销售团队 + 云市场 (AWS/GCP Marketplace) |

## 三、市场规模

### TAM → SAM → SOM

| 层 | 估算 |
|------|------|
| **TAM** (全球 DevOps 工具市场) | $15B (2025) |
| **SAM** (AI 辅助开发工具) | $3B |
| **SOM** (Agent 编排/可信执行) | $300M (新兴市场) |

### 增长驱动

- 企业 AI 采用率从 2024 年的 30% → 2026 年的 70%+
- Agent 执行能力越来越强 → 企业"用还是不用"的矛盾越来越尖锐
- 监管要求趋严（EU AI Act）→ 审计需求

## 五、关键风险 & 应对

| 风险 | 概率 | 影响 | 应对 |
|------|------|------|------|
| GitHub Copilot 直接做审批 Agent | 中 | 高 | 快跑 + 深度差异化（行业模板、合规） |
| Agent 能力不够，编排也没用 | 低 | 中 | 审批节点兜底，不依赖 Agent 完美执行 |
| 企业采购周期长 | 高 | 中 | 先做 PLG（个人/小团队用起来），再推企业 |
| 开源被大厂 fork | 低 | 中 | 品牌 + 社区粘性 + 企业特性闭源 |
| Agent API 成本不可控 | 中 | 低 | Token 限额 + 智能路由 + 模型降级 |
